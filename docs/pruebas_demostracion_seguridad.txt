PRUEBAS DE DEMOSTRACION DE SEGURIDAD EN TIEMPO REAL — NiXon.fear (T01-T10)
==============================================================================
Lenguaje sencillo, paso a paso. No se toca codigo. Solo navegador + curl.
BASE = http://localhost:8080 (docker-compose.yml:1-7 mapea "8080:80").

------------------------------------------------------------------------------
0. PREPARACION (hacer una sola vez, 5 minutos)
------------------------------------------------------------------------------

0.1 Levantar el juego con Docker:
  Paso 1: abre PowerShell en la carpeta del proyecto (donde esta docker-compose.yml).
  Paso 2: ejecuta:
    docker compose up --build
  Paso 3: abre el navegador en:
    http://localhost:8080/login.php
  Que ver: la pantalla "TERMINAL DE ACCESO". Si ves error de Mongo, revisa
  tu archivo .env (variable MONGODB_URI). Ver config/database.php:19-25.

0.2 Crear las cuentas demo (si no existen):
  Paso 1: en otra terminal ejecuta:
    php scripts/crear_usuarios_demo.php
  Esto crea (ver scripts/crear_usuarios_demo.php:33-34):
    Admin   : admin_nixon@nixon.fear  / Admin123!  (rol admin)
    Jugador : player_nixon@nixon.fear / Player123! (rol jugador)
  Paso 2: para la prueba IDOR necesitas UN SEGUNDO JUGADOR. Registra uno
  a mano en http://localhost:8080/register.php (ejemplo):
    player2@nixon.fear / Player123!
  O usa curl (ver paso T01 para el token CSRF primero).

0.3 Como obtener el token CSRF (lo necesitaras en casi todo):
  Opcion A (navegador, facil para demo):
    1. Abre http://localhost:8080/levels/level1.php (logueado).
    2. Pulsa F12 > pestana Consola, escribe:
         window.NIXON.csrfToken
       y copia el valor. Ver public/levels/level1.php:41-44.
    3. En login/register/notes el token tambien esta en el HTML como:
         <input type="hidden" name="csrf_token" value="...">
       Ver public/login.php:65. Click derecho > Ver codigo fuente, copia value.
  Opcion B (curl, para jar/cookies):
    1. GET login para cookie + token:
         curl -c jar.txt http://localhost:8080/login.php -o login.html
       Abre login.html, busca csrf_token, copia el value en TOKEN.
  Guarda en variables de tu terminal (PowerShell):
    $BASE="http://localhost:8080"
    Usa -b jar.txt -c jar.txt en cada curl para mantener sesion.
    Usa un jar distinto por usuario: jarA.txt (jugador1), jarB.txt (jugador2), jarAdmin.txt.

0.4 Crear 2 notas, una por usuario (para IDOR T03/T04):
  Paso 1: loguea jugador A (player_nixon) y saca su TOKEN_A (opcion A/B).
  Paso 2: crea nota de A:
    curl -b jarA.txt -c jarA.txt -X POST "$BASE/api/notes_create.php" `
      -H "Content-Type: application/json" `
      -d '{"level":"level1","category":"libreta","note_text":"nota secreta A","impact":"normal","csrf_token":"TOKEN_A"}'
  Esperado: HTTP 201 cuerpo exacto:
    {"status":"success","message":"NOTA REGISTRADA EN EL ARCHIVERO.","id":"<24hex>"}
  Ver public/api/notes_create.php:99. Guarda el id como ID_A.
  Paso 3: repite con jugador B (player2), guarda ID_B.
  Como ver los id despues: GET "$BASE/api/notes_list.php?level=level1" con cada jar.
  Ver public/api/notes_list.php:77-78.

0.5 Donde mirar en el navegador (para TODAS las pruebas):
  F12 > pestana Network (Red): haz click en cada peticion y mira:
    - Status (codigo HTTP), Response Headers (Allow, Location, Set-Cookie,
      Content-Security-Policy, HX-Redirect), Response/Preview (cuerpo JSON).
  F12 > Application > Cookies: mira PHPSESSID (HttpOnly, SameSite=Strict,
  Secure solo en HTTPS). Tras login el valor CAMBIA (regenerate).
  F12 > Consola: para los fetch() de T03/T04/T08.

T03 — IDOR LECTURA (403 ajena / 200 propia / 404 inexistente)
------------------------------------------------------------------------------
QUE hacer (ya tienes ID_A de la preparacion 0.4):
  1. Jugador B intenta leer nota de A (ataque):
     curl -b jarB.txt "$BASE/api/notes_get.php?id=ID_A" -i
  2. Jugador A lee su propia nota (legitimo):
     curl -b jarA.txt "$BASE/api/notes_get.php?id=ID_A" -i
  3. ID inexistente pero con formato valido (24 hex inventado):
     curl -b jarA.txt "$BASE/api/notes_get.php?id=000000000000000000000000" -i
  4. ID malformado:
     curl -b jarA.txt "$BASE/api/notes_get.php?id=hola" -i
  5. Consola del navegador (logueado como B, F12 > Consola):
     fetch("/api/notes_get.php?id=ID_A", {credentials:"include"}).then(r=>r.text().then(t=>console.log(r.status,t)))
COMO mirar:
  Network > notes_get.php > Status + Preview. Fijate que el cuerpo es JSON
  con llaves status/message. Codigo: public/api/notes_get.php:66-74.
QUE SE ESPERA (cuerpos exactos, ver public/api/notes_get.php:31-40):
  1. Ajena (B lee A): HTTP 403
     {"status":"error","message":"ACCESO DENEGADO."}
  2. Propia (A lee A): HTTP 200
     {"status":"success","message":"NOTA RECUPERADA.","note":{...}}
  3. Inexistente: HTTP 404
     {"status":"error","message":"NOTA NO ENCONTRADA."}
  4. Malformado: HTTP 400
     {"status":"error","message":"IDENTIFICADOR INVÁLIDO."}
  Clave demo: 403 != 404. El 403 confirma que el ID existe pero no es tuyo;
  el 404 que no existe nada con ese ID. Ver detalle en docs/justificacion_IDOR.txt.

T08 — CSRF (403 sin/malo, 200 con bueno, nunca en query)
------------------------------------------------------------------------------
QUE hacer (usa TOKEN_A valido de window.NIXON o hidden input):
  1. POST mutante SIN token:
     curl -b jarA.txt -X POST "$BASE/api/save_progress.php" -H "Content-Type: application/json" -d '{"level":"level1","step":1,"completed":false}' -i
     Codigo: public/api/save_progress.php:36-39.
  2. POST con token MALO (de otra sesion o inventado):
     curl -b jarA.txt -X POST "$BASE/api/save_progress.php" -H "Content-Type: application/json" -d '{"level":"level1","step":1,"completed":false,"csrf_token":"malo123"}' -i
  3. POST con token en QUERY (prohibido, debe fallar):
     curl -b jarA.txt -X POST "$BASE/api/save_progress.php?csrf_token=TOKEN_A" -H "Content-Type: application/json" -d '{"level":"level1","step":1,"completed":false}' -i
  4. POST con token BUENO en cuerpo (ok):
     curl -b jarA.txt -X POST "$BASE/api/save_progress.php" -H "Content-Type: application/json" -d '{"level":"level1","step":1,"completed":false,"csrf_token":"TOKEN_A"}' -i
  5. POST con token bueno en CABECERA (ok, para fetch):
     curl -b jarA.txt -X POST "$BASE/api/save_progress.php" -H "Content-Type: application/json" -H "X-CSRF-Token: TOKEN_A" -d '{"level":"level1","step":1,"completed":false}' -i
  6. Consola navegador: token viejo tras re-login ya no vale (rotate).
     Ver src/Controllers/AuthController.php:340-348 y 364-370.
COMO mirar:
  Network > save_progress.php > Preview. Compara los 5 cuerpos.
  Codigo CSRF: src/Security/Csrf.php:25-31 (hash_equals) + AuthController.php:133-142.
QUE SE ESPERA:
  1. Sin token: HTTP 403 {"status":"error","message":"TOKEN DE SEGURIDAD INVÁLIDO."}
  2. Token malo: HTTP 403 mismo cuerpo.
  3. Token en query: HTTP 403 mismo cuerpo (se ignora el query, nunca se lee).
  4. Token bueno cuerpo: HTTP 200 {"status":"success","message":"PROGRESO GUARDADO."}
  5. Token bueno cabecera: HTTP 200 mismo cuerpo.
  Tras login/logout el token viejo da 403 (rotate). Ver src/Security/Csrf.php:33-36.

ANEXO: TABLA RAPIDA HTTP + CUERPO (para el jurado)
------------------------------------------------------------------------------
401 SESIÓN NO AUTORIZADA.   -> sin login en API (notes_*.php, save_*, reset, validate).
403 TOKEN DE SEGURIDAD INVÁLIDO. -> CSRF malo/ausente (todos los POST/PUT/PATCH/DELETE).
403 ACCESO DENEGADO.        -> IDOR (nota ajena) o user_id ajeno sin ser admin, o jugador en panel GM.
404 NOTA NO ENCONTRADA.     -> ID valido pero no existe nada (o admin con ID inexistente).
400 IDENTIFICADOR INVÁLIDO. / NIVEL INVÁLIDO. / LÍMITE INVÁLIDO. etc. -> entrada malformada.
405 MÉTODO NO PERMITIDO. + Allow exacto -> metodo HTTP equivocado.
201 NOTA REGISTRADA EN EL ARCHIVERO. (create) / 200 NOTA RECUPERADA. (get) /
200 ARCHIVERO RECUPERADO. (list) / 200 NOTA ACTUALIZADA. (update) /
200 NOTA ELIMINADA DEL ARCHIVERO. (delete) / 200 PROGRESO GUARDADO. / 200 NIVEL REINICIADO.
302 Location: login/welcome + Set-Cookie nuevo -> login valido / pagina sin auth.
Credenciales inválidas. (con punto, C mayuscula) -> todo fallo de login/register/bloqueo.
